# 保障高速服务区充电网络韧性协同基础服务

本项目提供综合交通运输业务共享的服务端基础能力：在运营机构、交通节点、操作者、
结构化参考资料、角色权限、请求幂等、SQLite 事务与哈希串联审计之上，提供一条完整的
**干线新能源重卡充电保障服务**——面向节假日服务区充电桩检修叠加站点功率限额的高压场景，
为每趟运输生成带有效期、说明余量的补能计划，并对多站时隙实施原子锁定。

## 能做什么

### 网络与任务输入
- 车辆档案：电池容量、空/重载能耗曲线、额定载重、保底电量、是否抢险车辆。
- 干线与站点：走廊长度、平均车速、站点桩号、物理充电桩（额定功率）。
- 站点设备：站点/充电桩检修窗口、站点分时功率限额。
- 道路通行版本：版本号递增发布，路段封闭与绕行增量里程。
- 运输任务：剩余续航（初始电量）、载重、任务时限、发车时间、指定道路版本、优先级。

输入全部通过接口登记并纳入审计。规划结果每张计划腿标注**到站剩余 kWh / 折算公里余量、
任务时限余量（分钟）、每段的站点功率余量（kW）**，计划本身带 `valid_from / valid_until`。

### 补能计划
- 按当前道路版本的封闭段计算实际行驶里程（含绕行）与时间，按载重线性插值能耗。
- 在"最远可达 + 满足时限"的站点上，按 15 分钟时隙模拟可用功率（检修置零、
  分时限额取 min、扣除既有占用），把一次充电按功率档位切分并汇总为每站一条计划腿，
  占用按逐时隙真实取功记账，功率限额校验偏保守、绝不超载。
- 续航内无可用站或无法在时限前完成补能时返回不可行及原因（不生成可确认的空计划）。

### 确认、锁定与幂等
- 司机确认在**单个 SQLite 写事务**内同时锁定多个站点的时隙：物理桩唯一索引 +
  每个时隙站点总取功 ≤ 有效功率上限。任一站/任一时隙失效则整笔回滚，**不留下幽灵占用**。

- 同一 `request_id` 重试确认返回原预约且不重复扣减容量；并发重试同样只成功一次。
- 计划过期、首个时隙已开始、已有生效预约时拒绝确认，避免双计划竞争。
- 进程重启后，未到站的预约、逐时隙占用、计划链与事件链全部继续有效。

### 抢险优先权
- 抢险确认时自动解除与其时隙冲突的、**尚未开始**的普通预约（含排队容量冲突），
  释放时隙并为被挤车辆生成不撞抢险时隙的新待确认计划。
- 任何**已开始的充电会话**（以及 completed/faulted 会话事实）受物理保护：
  抢险不能挤掉，此时抢险确认整体回滚，不留任何半占用。
- 抢险之间不互挤。

### 按事实重规划
故障、排队超时、提前到达、临时道路封闭四种事件都以**已完成/中断会话的实充 kWh 事实**
为能量锚点（初始电量 − 已行驶里程×能耗 + 累计实充），结合最新道路版本重新规划；
旧预约的未到站时隙释放，计划状态置 `superseded`，事件链与计划链可追溯每次改派原因。

### 运营接口
- `GET /trips/{id}/safety`：当前能量锚点、各站与终点是否仍可安全抵达（含已锁定计划路径复算）。
- `GET /trips/{id}/timeline`：计划版本链与事件链，回答"一次改派为何发生"。
- `GET /stations/{id}/power`：逐 15 分钟时隙的在线桩功率、分时限额、检修状态、
  已占用 kW 与真实可用 kW，并逐桩标注空闲/占用/检修。

## 目录

- `src/transport_coordination/`
  - `charging.py`：纯领域规划（能量模型、道路版本、15 分钟功率时隙模拟、余量与可达性）。
  - `charging_service.py`：建档、计划、确认/锁定、会话事实、事件重规划、运营查询。
  - `storage.py`：扩展后的 23 张表（充电领域新增 17 张）、物理桩部分唯一索引、写事务串行锁。
  - `api.py`：新增 16 个 POST + 5 类 GET 路由。
  - `charging_acceptance.py`：节假日完整剧本的离线验收。
  - 其余为基础权限、幂等、审计链、时钟与 HTTP 边界。
- `tests/`：规划器单元、服务集成、HTTP 路由、存储事务、离线验收共 41 个测试。

## 环境

- Linux
- Python 3.11 或更高版本
- 运行时仅使用 Python 标准库和 SQLite

## 测试

```bash
PYTHONPATH=src python3 -m unittest discover -s tests -v
```

## 构建检查

```bash
python3 -m compileall -q src tests
```

## 离线验收

```bash
PYTHONPATH=src python3 -m transport_coordination.acceptance
PYTHONPATH=src python3 -m transport_coordination.charging_acceptance
```

充电验收命令在临时 SQLite 数据库中完整演绎：A 站单桩检修 + 全站 150kW 限额下的
计划/确认/重试幂等，抢险挤占未开始预约、已开始会话阻挡第二抢险并回滚，
故障按实充事实重规划、确认后遇道路封闭按版本 2 再规划，运营安全看板与安全/改派/功率三类查询，
以及进程重启后未到站预约与占用原样保留；成功时输出一行 `status` 为 `ok` 的 JSON，
退出码 0。

## HTTP 服务

```bash
PYTHONPATH=src python3 -m transport_coordination.api --database transport_coordination.sqlite3 --host 127.0.0.1 --port 8080
```

健康检查使用 `GET /health`。写入接口通过 `X-Actor-Id` 标识操作者，所有写接口以
`request_id` 幂等，服务重启后 SQLite 中的业务状态和审计历史继续保留。

## 主要接口一览

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| POST | `/vehicles` | 登记车辆（能耗曲线、保底电量、优先级） |
| POST | `/corridors` | 登记干线 |
| POST | `/stations` / `/chargers` | 登记站点与物理桩 |
| POST | `/station-state` | 站点启停（版本递增） |
| POST | `/station-outages` / `/charger-outages` | 检修窗口 |
| POST | `/power-windows` | 分时功率限额 |
| POST | `/road-versions` | 递增发布道路通行版本（封闭/绕行） |
| POST | `/trips` | 创建运输任务（续航、载重、时限、道路版本） |
| POST | `/energy-plans` | 生成带有效期与余量的补能计划 |
| POST | `/plan-confirmations` | 司机确认，多站时隙原子锁定 |
| POST | `/arrivals` | 到站登记（明显早到会被拒绝并引导重规划） |
| POST | `/session-starts` / `/session-completions` | 充电会话事实（实充 kWh） |
| POST | `/trip-events` | 故障/排队超时/提前到达/道路封闭触发按事实重规划 |
| GET | `/trips/{id}/safety` | 安全可达判断 |
| GET | `/safety-board?corridor_id=` | 调度看板：哪些在途车辆仍可安全抵达、哪些告急 |
| GET | `/trips/{id}/timeline` | 改派原因链 |
| GET | `/stations/{id}/power` | 逐时隙真实可用功率 |
| GET | `/plans/{id}` | 查询计划（含余量、逐时隙取功） |
